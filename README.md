# Web Store على GitHub Pages

هذه الحزمة خاصة بالمستودع:
https://github.com/AH1310/Web-Store

الرابط المتوقع بعد تفعيل Pages ونجاح النشر:
https://ah1310.github.io/Web-Store/

## رفع الملفات

1. فك ضغط ZIP بالكامل في مجلد.
2. افتح المستودع على GitHub.
3. Add file → Upload files.
4. ارفع كل محتويات المجلد في جذر المستودع، بما فيها index.html وملف .nojekyll.
5. Commit changes إلى الفرع الافتراضي لديك.

لا ترفع ملف ZIP نفسه. هذه ملفات ثابتة جاهزة؛ لا تحتاج Node.js أو ملف نشر .cmd أو أمر npm للنشر على GitHub Pages.

## تفعيل Pages

من المستودع: Settings → Pages → Build and deployment.
Source: Deploy from a branch.
Branch: اختَر الفرع الذي رفعت عليه الملفات (عادة main).
Folder: /(root).
اضغط Save، وانتظر نجاح عملية Pages في Actions ثم افتح رابط Visit site الظاهر في الإعدادات.

تأكد أن المستودع Public إذا كنت تستخدم GitHub Free. الرابط لا يعمل بمجرد رفع الملف؛ يجب تفعيل Pages ونجاح النشر.

## الحسابات والبيانات

الحسابات وقاعدة البيانات والإشعارات والتطبيقات تبقى على مشروع ah13-store-e0f08 الحالي. لا تحذف هذا المشروع أو قاعدة البيانات، ولا تنشئ حساب مدير جديد. الحزمة تستخدم بيانات الربط نفسها، ولا تغيّر كلمة مرور أي حساب. صلاحيات حذف التطبيقات والملكية تبقى كما نُشرت سابقًا.

في لوحة مشروعك الحالية افتح Authentication → Settings → Authorized domains → Add domain، وأضف:
ah1310.github.io

اكتب النطاق فقط، بدون https:// وبدون /Web-Store/.

المتصفح يعتبر رابط GitHub موقعًا مختلفًا، لذلك قد تحتاج تسجيل دخول مرة واحدة بنفس بريدك وكلمة مرورك القديمة. البيانات داخل حسابك لا تنتقل إلى GitHub ولا تُحذف.

رفع ملفات GitHub لا ينشر قواعد قاعدة البيانات. استخدم القواعد الأخيرة التي نُشرت من حزمة حذف تطبيق الناشر؛ لا تستبدلها بقواعد مفتوحة للعامة.

## الإضافات في هذه الحزمة

- الإدارة تعرض إشعارات المتجر وتسمح بحذفها، وتتيح حذف تقييم مخالف بعد تأكيد الإجراء.
- حذف المستخدم لتطبيقه كان موجودًا في الحزمة؛ بقي كما هو: حذف منطقي يخفيه من المتجر ويحتفظ بسجل الناشر.
- نموذج النشر يبيّن الفئة ونموذج تحقيق الدخل (مجاني، إعلانات، اشتراك، شراء داخل التطبيق، أو دخل عبر الموقع الخارجي). هذه بيانات تعريفية يحددها الناشر، وليست إثباتًا للدخل أو تحصيلًا ماليًا من المتجر.
- فحص اسم التطبيق يطبع المسافات ويقارن الحروف دون حساسية لحالة الأحرف أو التشكيل، ويرفض الاسم الظاهر مسبقًا في الكتالوج قبل النشر.

## إضافات تجربة التطبيق والإحصاءات

- نموذج النشر وتعديل التطبيق يقبلان حتى 5 لقطات شاشة مضغوطة، ويديران الإصدار ومتطلبات التشغيل وسياسة الخصوصية وموقع المطور.
- تُحفظ لقطات الشاشة المضغوطة داخل سجل التطبيق في Realtime Database بحد إجمالي يقارب 750 كيلوبايت. هذا مناسب للنموذج الحالي؛ عند التوسع التجاري انقل الصور إلى Firebase Storage مع قواعد رفع مناسبة.
- صفحة التفاصيل تعرض الصور والمطور والفئة ونموذج الربح المعلن والمراجعات. ترتيب الأعلى تقييمًا يستخدم متوسطًا موزونًا بعدد التقييمات، ويضع التطبيقات بلا تقييمات بعد التطبيقات المقيمة.
- عدادات المتجر تسجل مشاهدة صفحة التفاصيل ونقرة فتح التطبيق فقط. لا يمكن التحقق من تنزيل أو تثبيت مواقع الويب الخارجية من صفحة المتجر. تتطلب صلاحيات Firebase المناسبة؛ عند رفضها تظهر الإحصاءات غير متاحة ولا يُعرض رقم تنزيل مصطنع.
- التسجيل الحالي يوفّر حساب مستخدم أو مطور. لا يوجد اشتراك مدفوع أو ترقية حساب تلقائية؛ لا يُفعّل توثيق مدفوع دون تحقق دفع وخادم موثوق.

## ملاحظة قواعد البيانات

تتضمن الحزمة فحص تكرار الاسم من واجهة النشر، لكنها لا تتضمن قواعد Realtime Database المنشورة. لذلك لا يمكن ضمان منع التكرار في سباق متزامن أو عند كتابة البيانات خارج الواجهة إلا بعد إضافة قيد ذري لقواعد/خادم Firebase. لم تُفتح القواعد أو تُستبدل بقواعد عامة. تعتمد أدوات الإدارة الجديدة على صلاحيات المدير الموجودة في قواعد مشروع Firebase؛ اختبر حذف الإشعار والتقييم بحساب المدير قبل النشر.

## التحديثات القادمة

ارفع الملفات المعدلة إلى نفس الفرع؛ GitHub Pages سيعيد النشر. الرابط يبقى نفسه. احتفظ بملف firebase-config.json والأيقونات وmanifest وsw.js بجوار index.html، لأن كل المسارات مضبوطة لمجلد Web-Store.

ملف index.html يحتوي الستايل والجافا سكريبت. إعداد حماية CSP داخل الصفحة وبصماته مرتبطة بمحتوى الستايل والجافا سكريبت؛ تغييرهما يدويًا يحتاج إعادة حساب البصمات حتى لا يمنع المتصفح تشغيلهما.

عند تعديل ملفات الواجهة، غيّر رقم CACHE في sw.js حتى تتجدد ذاكرة التثبيت. عمل الواجهة دون اتصال لا يعني أن الحسابات أو التطبيقات الخارجية تعمل دون اتصال.

## المزايا المحفوظة

شعار Web Store، العربية/الإنجليزية، النهاري/الليلي، القائمة الجانبية، صورة الحساب، النشر الفوري، حتى 20 كلمة مفتاحية، تنزيل وحفظ في المكتبة وفتح داخل المتجر، تقييمات وبلاغات وإشعارات، إدارة وحظر، حذف التطبيق بواسطة ناشره مع تأكيد، وكلمة مرور جديدة 8 أحرف على الأقل مع زر العين.

المواقع الخارجية التي تمنع التضمين لا يمكن إجبارها على الفتح داخل iframe؛ الفتح الخارجي متاح عند الحاجة فقط.

هذه نسخة GitHub Pages معدلة من آخر حزمة، ولم يتم رفع الملفات أو تفعيل Pages من طرف المساعد. تم فحص الأصول، ومجال PWA تحت /Web-Store/، وبصمات الحماية مع LF وCRLF، ووجود وظائف النسخة الأخيرة. يلزم تجربة الدخول والنشر بعد تفعيل الرابط.

## محركات البحث

canonical ووسوم المشاركة وsitemap.xml مضبوطة للرابط الجديد. بعد نجاح النشر أضف الموقع إلى Google Search Console وأرسل:
https://ah1310.github.io/Web-Store/sitemap.xml

robots.txt الموجود في مجلد المشروع لا يتحكم وحده في جذر نطاق ah1310.github.io؛ لا تعتمد عليه كوسيلة لحماية البيانات. صفحة المساعدة تحتوي noindex. الظهور والترتيب في نتائج البحث غير مضمونين.

## تحسينات جلسة الهاتف والمكتبة

- يستخدم تسجيل الدخول Firebase Auth مع browserLocalPersistence، لذلك تبقى الجلسة بعد إعادة تحميل الصفحة حتى تسجيل الخروج أو مسح بيانات المتصفح.
- تُزامن مكتبة التطبيقات مع Firebase وتُحفظ نسخة محلية احتياطية خاصة بالحساب على الجهاز الحالي. التخزين المحلي وحده لا ينتقل إلى جهاز آخر، ومسح بيانات الموقع يمسحه.
- الضغط على صورة التطبيق أو اسمه يفتح صفحة تفاصيل كاملة تشمل التقييمات والمراجعات، والضغط على «إضافة للمكتبة» لا يثبت ملفًا على الجهاز. إزالة التطبيق من المكتبة لا تحذفه من الهاتف.
- اختيار «أخرى» في نموذج النشر/التعديل يُظهر خانة لوصف الفئة الفرعية ويجعلها مطلوبة.
- حُذف تحديث غير لازم لمسار appOwners من عملية حذف التطبيق لتقليل تعارض الصلاحيات. قد تحتاج قاعدة Realtime Database الحالية إلى سماح محدد لمالك التطبيق بحذف سجل التطبيق من catalog؛ راجع ملف Web-Store-Technical-Next-Steps-AR.md، ولا تستبدل قواعد Firebase الحالية بقواعد عامة.

تفاصيل خطة التحصيل ورسوم بوابات الدفع ومتطلبات خادم webhook موثوق موضحة في Web-Store-Technical-Next-Steps-AR.md. لا يوجد دفع حي أو تحقق مدفوعات في هذه الحزمة.

## ملفات الإطلاق الإضافية

- مجلد `firebase-setup/` يشرح إعداد Firebase من البداية، وأمان القواعد، وتأمين مراجعة الأدمن وحجز الأسماء.
- مجلد `google-search/` يحتوي نسخًا مرجعية من `robots.txt` و`sitemap.xml` وخطوات Google Search Console. يجب أن تبقى النسختان الفعليتان في جذر المشروع عند الرفع.
- إرسال التطبيق يحفظ حالة `pending` حتى يراجعه الأدمن؛ ولا يظهر في الكتالوج العام قبل الموافقة.
- لا يوجد نشر أو تعديل لقواعد Firebase أو Cloud Functions من الحزمة؛ يلزم تنفيذها في حساب مالك المشروع كما هو موضح في الدليل.
